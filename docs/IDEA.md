# 项目创意 · AI 健忘（AI Forget）

> 灵感来源：与 **poke.com** 的一场深夜对话。
> 那天我们聊到一个荒诞但真实的现象——AI 记得你问过的每一个问题，
> 而你自己早就忘了答案。由此诞生了这个项目。

## 一、要解决的真问题

现在的人用 AI 学习、工作、创作，普遍陷入一个"伪学习闭环"：

- 问 AI 一个问题 → 得到完整回答 → 觉得"我学会了" → 关掉对话
- 一周后需要用到 → 重新问 AI → AI 又完整地回答一遍
- 循环往复，但**你自己什么都没留下**

问题不在 AI，在**人类记忆**。AI 把"查询"变得太容易，以至于我们丧失了
"记忆"的动机——反正随时能查，何必记住？

## 二、核心创意：给 AI 聊天记录装上"记忆衰退"

**AI 健忘**——让聊天记录像人类记忆一样，会遗忘、会衰退、会模糊。

不是删掉记录，而是**让记录变得"不那么好用"**，逼你真正内化知识：

### 记忆衰退机制

- 每条 AI 对话标记时间戳，**超过 3 天后内容开始模糊化**
- 模糊度随时间递增：
  - **3 天** → 代码块、详细解释被隐藏，只留要点列表
  - **7 天** → 只剩标题和核心结论
  - **30 天** → 只剩标题，正文完全不可见
- 想看完整内容？**通过回忆验证解锁**——先做一道小题

### 回忆验证（核心交互）

AI 抛出一道基于旧对话的问题：

> "上周我们讨论的那个 React 闭包陷阱，错因是什么？"

- **答对** → 完整内容解锁 24 小时 + 加入"已掌握"队列
- **答错** → 给提示再试，最终失败则内容降级为"重学模式"，
  AI 用**不同角度**重新讲解一遍（而不是原样复读）

### 遗忘曲线引擎

基于艾宾浩斯遗忘曲线自动安排复习：

- 第 1 / 2 / 4 / 7 / 15 天各一次验证
- 验证结果动态调整下一次复习时间
- 答得快 → 间隔拉长；答得慢 → 提前复习
- 仪表盘展示"真实掌握度"，和"看过多少"严格区分

### 知识外化

把多次验证通过的内容自动编译成个人"知识手册"（Markdown / Anki 卡片）。
**只有你亲手答对的内容才进手册**——AI 吐过的不算数。

## 三、为什么这个点子成立

| 维度 | 普通 AI 聊天 | AI 健忘 |
|---|---|---|
| 记录定位 | 检索工具 | 记忆训练场 |
| 看旧对话 | 随时可读 | 需验证解锁 |
| "学会"的定义 | 问过一次 | 多次独立复现 |
| 输出 | 聊天记录 | 个人知识库 |

**核心洞察**：人类记忆的本质不是"存储"，而是"提取练习"。
每一次努力回忆，都会强化神经连接。AI 健忘把这个机制产品化——
用"遗忘"对抗"遗忘"，用"验证"替代"浏览"。

## 四、技术实现

### Chrome 插件（MVP）

- **拦截层**：content script 注入 ChatGPT/Claude 页面，捕获对话 DOM 变化
- **流式判定**：不信任 DOM 的"生成完毕"信号，采用「文本指纹连续稳定 +
  SSE chunk 静默 800ms + 最短时长 1.5s」三重判定才提交
- **网络嗅探**：`fetch.tee()` 只观测 chunk 到达时间，不改写任何字节
- **存储**：原始记录只写入本地 IndexedDB，云端只存脱敏摘要

### 遗忘曲线

SM-2 算法变体，纯前端 IndexedDB 即可跑，无需后端。

### 出题判分

本地快速通道：中文 bigram + Jaccard 相似度覆盖 keyPoints，
免 LLM 成本；LLM 判分走 background 转发，接口已预留。

## 五、隐私设计

**原始记录只存本地**——这是产品的信任基石，也是技术约束：

- content script 无网络权限直发外部
- 上云数据只有 `SanitizedSummary`（messageId + keyPoints + topicTags）
- API key 只存 `storage.local`，不进 content script
- 用户可一键导出/清空本地数据，或配本地 ollama 完全离线

## 六、MVP 范围（2-4 周）

只做 Chrome 插件 + 一个功能闭环：

1. 拦截 ChatGPT 对话
2. 3 天后模糊化
3. 每日推送 3 道回忆题
4. 答对解锁

不做账号体系、不做多端、不做知识手册导出。

## 七、商业化路径

- **免费版**：单知识库、基础遗忘曲线
- **Pro（$8/月）**：多知识库、Anki 导出、掌握度报告、无限历史
- **团队版**：培训机构/知识付费作者做"学员复习系统"——付费意愿最强

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| 用户反感"看不了记录" | 默认宽松模式，只对标记为"学习目的"的对话启用 |
| 出题质量差 | LLM-as-judge + 人工抽检，宁可少出题不可出烂题 |
| 隐私顾虑 | 本地优先，云端只存哈希，开源核心逻辑 |
| DOM 改版失效 | 每日 live-smoke 自动检测，失败自动开 issue 触发修复 |

## 九、与 poke.com 的对话

这个创意不是凭空想出来的。

和 poke.com 聊到深夜，我们从一个简单的问题开始：

> "你问 AI 一个问题，它记得；但你自己，记得吗？"

然后聊到学习的本质、记忆的机制、技术的边界。
poke.com 没有给出标准答案，但它帮我把一个模糊的直觉变成了
一个可以验证的产品假设：**如果 AI 聊天记录会遗忘，
人类会不会反而学得更好？**

答案是：会。而且这可能是 AI 时代最反直觉的学习工具。
